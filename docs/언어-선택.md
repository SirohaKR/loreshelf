# 언어 · 기술 선택

> **추천: Dart** (서버) + HTML/CSS/JS (1단계 화면) → 나중에 Flutter 앱
> 8개 언어를 같은 기준으로 비교한 결과 Dart 88점, 2위 C# 72점.
> Flutter 계획을 빼고 계산해도 Dart가 1위지만 C#과 차이가 작아서, **Flutter 앱을 안 만들기로 하면 C#도 좋은 선택**이에요 (6절).

## 4. 같은 코드를 언어별로 — 직접 읽어 보고 판단하기

"공개된 캐릭터 목록을 정렬 순서대로 가져오기"를 각 언어로 쓴 예예요. 어느 게 제일 편하게 읽히는지가 가장 중요한 판단 기준이에요.

**Dart**
```dart
class CharacterRepository {
  final Database db;
  CharacterRepository(this.db);

  List<Character> findPublic() {
    final rows = db.select(
        "SELECT * FROM characters WHERE visibility = 'public' AND deleted_at IS NULL ORDER BY sort_order");
    return rows.map(Character.fromRow).toList();
  }
}
```

**C#**
```csharp
public class CharacterRepository(SqliteConnection db)
{
    public List<Character> FindPublic() =>
        db.Query<Character>(
            "SELECT * FROM characters WHERE visibility = 'public' AND deleted_at IS NULL ORDER BY sort_order")
          .ToList();
}
```

**Kotlin**
```kotlin
class CharacterRepository(private val db: Connection) {
    fun findPublic(): List<Character> =
        db.prepareStatement("SELECT * FROM characters WHERE visibility = 'public' AND deleted_at IS NULL ORDER BY sort_order")
            .executeQuery()
            .use { rs -> generateSequence { if (rs.next()) Character.from(rs) else null }.toList() }
}
```

**TypeScript**
```ts
export class CharacterRepository {
  constructor(private db: Database) {}

  findPublic(): Character[] {
    return this.db
      .prepare("SELECT * FROM characters WHERE visibility = 'public' AND deleted_at IS NULL ORDER BY sort_order")
      .all() as Character[];
  }
}
```

**Go**
```go
func (r *CharacterRepository) FindPublic() ([]Character, error) {
	rows, err := r.db.Query("SELECT id, name FROM characters WHERE visibility = 'public' AND deleted_at IS NULL ORDER BY sort_order")
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	var list []Character
	for rows.Next() {
		var c Character
		if err := rows.Scan(&c.ID, &c.Name); err != nil {
			return nil, err
		}
		list = append(list, c)
	}
	return list, rows.Err()
}
```

**Python**
```python
class CharacterRepository:
    def __init__(self, db):
        self.db = db

    def find_public(self):
        rows = self.db.execute(
            "SELECT * FROM characters WHERE visibility = 'public' AND deleted_at IS NULL ORDER BY sort_order"
        ).fetchall()
        return [Character.from_row(r) for r in rows]
```

> Dart와 C#이 Java를 아는 사람에게 가장 익숙한 모양이에요. (C#은 `Dapper`, TypeScript는 `better-sqlite3`, Dart는 `sqlite3` 패키지 기준. 느낌 비교용이라 에러 처리는 생략.)

## 5. NAS 자원 비교 (대략)

| 언어 | Docker 이미지 | 대기 중 메모리 |
|---|---|---|
| Dart (네이티브 빌드) | 약 20MB (maple-ledger 실측 약 22MB) | 수십 MB |
| Go | 약 15~25MB | 수십 MB 이하 |
| C# (Native AOT) | 약 30~50MB | 수십 MB |
| C# (일반) | 약 100~200MB | 약 100MB 안팎 |
| TypeScript (Node) | 약 100~200MB | 약 50~100MB |
| Python | 약 150MB 이상 | 약 50~100MB |
| Kotlin / Java (JVM) | 약 200MB 이상 | 150~300MB |

Dart 외에는 이 프로젝트 기준으로 직접 재본 값이 아니라 일반적인 범위예요. 1인 사용이라 어떤 언어든 NAS가 못 버틸 수준은 아니고, 가벼움은 "다른 컨테이너와 같이 돌릴 때 여유" 정도의 차이예요.

## 6. 최종 추천과 바꿔야 할 조건

### 추천: **Dart**
1. **읽고 고칠 수 있음** — Java와 비슷한 문법이고, maple-ledger에서 이미 같은 구조를 봤어요.
2. **한 번 짜서 두 곳에서 씀** — 프롬프트 분류, 캐릭터 카드 변환, PNG 메타데이터 읽기를 `shared/`에 두면 Flutter 앱에서도 그대로 써요.
3. **배포 방식이 이미 검증됨** — maple-ledger와 같은 Dockerfile·NAS 절차를 그대로 써요.
4. 약점인 라이브러리 부족은 이 프로젝트 범위에서는 문제가 안 돼요. 필요한 것(SQLite·이미지·마크다운·템플릿·HTTP)은 모두 있어요(7절).

### 이럴 땐 다른 언어
| 조건 | 추천 | 이유 |
|---|---|---|
| **Flutter 앱을 안 만들기로 함** + 라이브러리·자료가 많은 쪽이 좋음 | **C#** | Java와 가장 비슷하고 생태계가 가장 탄탄. 점수 차이 5%p로 거의 동점 |
| 앱 없이 **웹만** 만들고, 화면과 서버를 한 언어로 통일하고 싶음 | **TypeScript** | 브라우저 JS를 어차피 써야 해서 언어가 하나로 줄어듦. 대신 읽기 편한 정도는 떨어짐 |
| 앞으로 회사·이직 등에서 **Java 경력을 쌓고 싶음** | **Kotlin** | Java 생태계 그대로, 코드는 더 짧음. NAS 메모리는 더 씀 |

## 8. 화면은 어떻게 만드나

| 화면 | 1단계 | 나중에 |
|---|---|---|
| **작업실** (로그인 후 편집하는 곳) | HTML + CSS + 바닐라 JS. `mockups/style.css`를 그대로 씀. 서버의 `/api/...`를 호출 | **Flutter 앱** (폰·PC)이 같은 `/api/...`를 호출 |
| **공개 블로그** | **서버가 HTML을 완성해서 보냄** (검색 노출, 링크 미리보기) | 그대로 |

- Flutter Web으로 블로그를 만들면 검색엔진 노출과 첫 화면 속도가 나빠서 블로그는 끝까지 서버 HTML로 가요.
- 작업실을 처음부터 Flutter로 하지 않는 이유: 목업이 이미 반응형 HTML/CSS라 바로 이어서 만들 수 있고, 앱은 기능이 안정된 뒤에 만들어도 API를 그대로 쓰기 때문이에요.
- 프롬프트 분류는 서버(Dart) 한 곳에만 두고 화면은 `/api/gen/parse`를 호출해요. 지금의 `prompt-parser.js`는 프로토타입으로만 남겨요.

## 9. 폴더 구조 (maple-ledger와 같은 규칙)

```
loreshelf/
├─ shared/                     ← 서버와 Flutter 앱이 같이 쓰는 순수 Dart 코드
│  └─ lib/
│     ├─ prompt_parser.dart    ← 프롬프트 자동 분류 (JS 프로토타입을 옮김)
│     ├─ character_card.dart   ← 캐릭터 카드 V2/V3 변환
│     └─ png_metadata.dart     ← PNG 생성 정보 읽기
├─ server/
│  ├─ bin/server.dart
│  ├─ migrations/              ← DB 변경 이력 (0001_init.sql, 0002_….sql)
│  ├─ lib/
│  │  ├─ core/                 ← DB 연결, 마이그레이션 실행, 인증, 공통 응답
│  │  └─ features/             ← 기능(=테이블 묶음)별 폴더
│  │     ├─ characters/        characters_repository / _service / _routes
│  │     ├─ worlds/  projects/  docs/  assets/  tags/  memos/  timeline/
│  │     ├─ chatbot/           ← chatbot_* 테이블
│  │     ├─ gen/               ← gen_* 테이블 (이미지 생성 기록)
│  │     ├─ game/  board/      ← game_*, board_* 테이블
│  │     ├─ blog/              ← 공개 페이지 (읽기 전용)
│  │     └─ auth/  settings/
│  ├─ templates/               ← 블로그 HTML 틀
│  ├─ test/                    ← schema_rules_test.dart 등
│  └─ web/                     ← 작업실 화면 (HTML/CSS/JS)
└─ app/                        ← (나중) Flutter 앱
```

**규칙: 테이블 접두어 = 기능 폴더 이름.** `chatbot_versions` 테이블을 고치고 싶으면 `features/chatbot/`만 보면 돼요. 자세한 이름 규칙은 [DB-설계.md](DB-설계.md).

## 10. Dart의 위험과 대비

| 위험 | 대비 |
|---|---|
| 서버용 자료가 Python·TS보다 적음 | maple-ledger에서 쓴 구조·패키지를 그대로 가져와서 새로 찾을 게 적음 |
| Claude 공식 Dart SDK 없음 | HTTP 요청 하나라 `claude_client.dart` 파일 하나로 감쌈 |
| 순수 Dart 이미지 처리가 느림 | 썸네일은 업로드 때 한 번만 생성해서 저장 |
| 필요한 패키지가 없을 때 | DB가 SQLite라 언어와 무관함. 최악의 경우 그 기능만 다른 언어로 작은 도구를 만들어도 같은 DB를 씀 |
| 나중에 언어를 바꾸고 싶을 때 | DB 설계·이름 규칙·API 모양이 언어와 독립적이라 서버만 다시 짜면 됨. 화면과 데이터는 그대로 |
