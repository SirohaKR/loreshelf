처음 코드를 열었을 때 어디부터 보면 되는지, 기능을 추가·수정할 때 무엇을 지키는지 정리한 문서예요.

- DB 이름 규칙·마이그레이션: [DB-설계.md](DB-설계.md)
- 왜 Dart인지: [언어-선택.md](언어-선택.md)

## 1. 폴더 구조

```
loreshelf/
├─ pubspec.yaml              Dart 작업 공간 (server + app, 2단계에 shared/ 추가)
├─ Dockerfile, docker-compose.yml   (서버 이미지는 작업 공간에서 app을 빼고 빌드)
├─ docs/                     문서 (flutter-공부노트.md = 앱 코드 설명)
├─ app/                      Flutter 앱 (보기 전용 1차) — 자세한 건 app/README.md
└─ server/
   ├─ bin/server.dart        시작점 (환경 변수 읽고 서버 켜기)
   ├─ migrations/            DB 변경 파일 0001_init.sql … (절대 고치지 말고 새 번호 추가)
   ├─ lib/
   │  ├─ app.dart            마이그레이션 실행 + 기능별 API 주소 모으기
   │  ├─ core/               공통: db(SQLite), migrations, http(JSON·오류·값 검사), owned(내 것인지 확인), passwords, context
   │  └─ features/<기능>/    기능 = 테이블 묶음. <기능>_repository.dart(SQL) / _routes.dart(API) / _service.dart(복잡한 처리)
   ├─ test/                  api_test(API 전체 흐름), schema_rules_test(DB 이름 규칙)
   ├─ tool/make_erd.dart     docs/erd.html 만들기
   └─ web/                   작업실 화면
      ├─ index.html
      └─ static/css/style.css, static/js/{app,api,ui,parts}.js, static/js/pages/*.js
```

## 2. 지키는 규칙

| 규칙 | 이유 |
|---|---|
| **SQL은 `*_repository.dart`에만** | DB를 바꿀 때 고칠 곳이 한 군데 |
| **화면에서 온 값은 `*_routes.dart`의 `_values()`에서 검사** (`requireStr`, `oneOf`, `colorOrNull`, `ownedIdOrNull` …) | 잘못된 값·남의 번호가 DB에 못 들어가게 |
| **번호를 받으면 `owned.dart`로 내 것인지 확인** | 계정이 늘어나도 남의 데이터를 못 건드리게 |
| **오류는 `throw ApiError('한국어 문구', 상태코드)`** | 화면에 그대로 보여 줌 |
| **화면 HTML은 `html\`...\`` 로만 만들기** (`ui.js`) | `${}` 안의 값이 자동 이스케이프돼서 캐릭터 이름 등에 HTML을 넣어도 실행되지 않음. `innerHTML`에 문자열을 직접 넣지 않기 |
| **DB 변경은 새 마이그레이션 파일로** | NAS의 실제 DB는 이미 앞 번호가 적용돼 있음 |
| 화면 문구는 존댓말 "~해요" 체 | 전체 톤 통일 |

## 3. 기능 추가하는 순서 (예: 메모 기능)

1. 테이블이 필요하면 `migrations/0002_….sql` 추가 → `dart test`로 이름 규칙 확인 → `dart run tool/make_erd.dart`
2. `lib/features/memos/memos_repository.dart` — SQL
3. `lib/features/memos/memos_routes.dart` — `register(Router r)`에 주소 등록, 값 검사
4. `lib/app.dart`의 목록에 `MemosRoutes(app).register` 한 줄
5. `test/api_test.dart`에 흐름 테스트 추가
6. 화면: `web/static/js/pages/memos.js` 만들고 `app.js`의 `ROUTES`와 메뉴에 추가
7. `server/CHANGELOG.md`에 사용자 입장의 변경 내용 기록

## 4. API 목록

모든 `/api/` 주소는 로그인이 필요해요 (`/api/auth/` 제외). 요청·응답은 JSON, 오류는 `{"error": "문구"}`.

| 주소 | 하는 일 |
|---|---|
| `GET /api/auth/me` | 내 정보, 계정 만들기가 필요한지(`needs_setup`) |
| `POST /api/auth/setup` | 첫 계정 만들기 (계정이 없을 때만) |
| `POST /api/auth/login` · `logout` | 로그인 / 로그아웃 (쿠키 `ls_session`, 30일) |
| `PUT /api/account/password` · `profile` | 비밀번호 / 이름 바꾸기 |
| `GET/PUT /api/settings` | 설정 (지금은 `theme`) |
| `GET /api/home` | 숫자 요약, 최근 캐릭터, 프로젝트 |
| `GET/POST /api/worlds`, `GET/PUT/DELETE /api/worlds/:id` | 세계관 — v0.2부터 화면에서 숨김 (예전 데이터용으로 남겨 둠) |
| `GET/POST /api/projects?genre_id=`, `GET/PUT/DELETE /api/projects/:id` | 프로젝트 (상세에 전용 + 연결 캐릭터, `genres`). 저장할 때 `genre_ids: [..]` — 빼고 보내면 태그는 그대로 |
| `GET /api/genres` · `POST /api/genres` · `DELETE /api/genres/:id` | 장르·세계관 태그 목록(기본 제공 + 직접 추가, 사용 수) / 직접 추가(같은 이름이면 기존 태그) / 직접 추가한 것만 삭제 |
| `POST /api/projects/:id/characters` · `DELETE …/:characterId` | 서재 캐릭터 연결(역할 포함) / 연결 끊기 |
| `GET /api/characters?scope=library&project_id=&world_id=&tag=&q=&favorite=1&recent=1&limit=` | 캐릭터 목록 |
| `POST /api/characters`, `GET/PUT/DELETE /api/characters/:id` | 캐릭터 (저장할 때 fields·traits·quotes·tags를 통째로 보냄) |
| `PUT /api/characters/:id/favorite` | 즐겨찾기 |
| `POST /api/characters/:id/move` | 저장 위치 옮기기 (`project_id: null` = 서재로) |
| `POST /api/characters/:id/fork` | 분기 (복사본, `source_character_id`에 원본) |
| `POST /api/characters/:id/assets` · `DELETE …/:assetId` | 갤러리에 넣기(`set_portrait`로 대표 지정) / 빼기 |
| `POST /api/assets` | 이미지 올리기 — 본문 = 파일 그대로, 파일 이름은 `x-file-name` 헤더(URL 인코딩). PNG·JPG·GIF·WEBP, 20MB |
| `GET /api/assets/:id/file` · `thumb` | 원본 / 썸네일(가로 480px JPEG) |
| `GET /api/tags` | 태그 목록 (자동완성) |
| `GET /api/search?q=` | 통합 검색 |
| `GET /api/trash`, `POST /api/trash/:kind/:id/restore`, `DELETE /api/trash/:kind/:id` | 휴지통 (kind = characters·worlds·projects) |

## 5. 알아 두면 좋은 동작

- **휴지통**: 삭제는 `deleted_at`만 채움. 프로젝트를 휴지통에 넣으면 그 전용 캐릭터도 목록에서 같이 숨음. 프로젝트를 **영구 삭제**하면 전용 캐릭터도 DB에서 같이 지워짐(CASCADE) — 화면이 미리 경고함.
- **이미지 저장**: `data/assets/u<사용자>/<sha256 앞 2자>/<sha256>.<확장자>` + `.thumb.jpg`. 같은 파일은 다시 저장하지 않고 기존 번호를 돌려줌. 형식은 확장자가 아니라 파일 앞부분으로 판단.
- **비밀 칸(`is_secret`)**: 1단계에선 표시만. 4단계 블로그 API가 이 칸을 서버에서 빼고 보냄.
- **태그**: 이름으로 저장하면 없는 태그는 자동 생성, 아무 데도 안 쓰이는 태그는 자동 정리.
- **화면 캐시**: `index.html`이 CSS·JS 주소에 `?v=<수정 시각>`을 붙이고, 정적 파일은 `no-cache`라 업데이트 후 바로 새 화면이 보임.

## 6. 테스트

```bash
cd server
dart analyze
dart test
```

`dart test`는 서버가 켜져 있으면 SQLite 파일이 잠겨서 실패할 수 있어요 (Windows). 개발 서버를 끄고 돌려요.

앱(`app/`) 테스트와 경로 관련 주의점은 [app/README.md](../app/README.md)에 있어요.

> **작업 공간 버전 맞춤**: 앱(Flutter SDK)이 `test_api`를 고정해서 서버의 `test`도 `^1.31.1`로 맞췄어요. Flutter를 올린 뒤 `flutter pub get`이 되면 다시 올려도 돼요.
